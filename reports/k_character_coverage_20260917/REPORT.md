# K1/K3 字符覆盖核验

32 是全局 batch64 中每次抽取的西文字图数量，不是训练字符表的大小；同批还可能含同字异字体的配对样本。因此 batch 大小既不需要等于52，也不需要一次包含所有字符。

训练集合为223个字体×89个西文码点=19,847张：26大写+26小写+10数字+27扩展拉丁字母。每个字体都有完整89种。无标点，不覆盖其他全部西文字符。

实际参与训练的覆盖由冻结代码 KSampler 回放得到。数据顺序按 FontDataset 的字体/字符排序重建，采样器哈希与执行锁核对，逐千步字体曝光计数与远端保存的 exposure 文件完全一致。两次运行都无 AMP 跳步。这里仅统计主训练，K3辅助配对另计，不会降低已见覆盖。

|模型|步骤|西文字种覆盖|每种字符累计曝光范围|西文字体×字符覆盖|全字种首次覆盖|
|---|---:|---:|---:|---:|---:|
|K1|10000|89/89|3414–3736|19824/19847 (99.884%)|第15步|
|K3|3857|89/89|1239–1471|18437/19847 (92.896%)|第15步|

K1并非“52个英文字母没有见全”：所有89种字符都被反复训练。但仍有23个具体字体×西文字符组合未抽中，说明有放回且偏重复杂字体的采样并不保证逐图遍历。K1假名字体×字符覆盖率为96.377%，注音99.875%；不能把字种覆盖100%写成所有字图覆盖100%。

建议下一数据版本增加“覆盖后再重采样”的机制：在保留script配额和复杂字体曝光预算的前提下，对每个字体的字符池按随机顺序循环，记录未见组合。该建议尚未执行；当前K3保持与K1匹配的主采样器。此次没有修改训练数据或停止训练。

新数据需要同时核对字符范围、字体去重/别名和训练验证划分；中文生成或西到中属于新增任务，须在独立版本注明配比。
