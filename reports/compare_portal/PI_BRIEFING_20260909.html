目标一句话：在「只给目标字体的若干汉字参考图」的条件下，生成该字体的数字、拉丁字母、假名、注音等非汉字字形，并检验改进是否真的提高了风格一致性（而不只是像素更像真值）。

1. 任务与数据（所有实验共用）

  • 数据：260 套字体；按字体划分为训练 228 / 验证 16 / 测试 16。
  • 每套字体：338 个汉字可作为风格参考；295 个目标字符（数字、拉丁、扩展拉丁、平假名、片假名、注音）。
  • 输入：内容图（要写哪个字）+ 目标字体的风格参考图；输出一张 96×96 字形图。
  • 当前主评测集：测试 16 套字体 × 分层抽取的 47 个字符 = 752 个样本；生成随机种子固定为 3407；采样器 DPM-Solver++，20 步，引导强度 7.5。

像素指标（L1 / SSIM / LPIPS）相对真值，只作诊断。论文主张的「风格像不像」要靠独立风格评测器与人工对照，不能只看像素分。

2. 实验在比什么（消融逻辑）

我们把「官方结构迁移模块」拆开，做成可对照的一组实验。名字是内部编号，下表用全称说明。每条箭头 = 一次只改一个因素。

F3b（新版） 重新设计的支持特征：仅用目标字体自身编码；笔画分桶抽样 相对 F2：规范后的支持特征 训练中 ~0.9万/8万；计划 2万步先评一次
风格评测器 独立训练的风格编码器 + 同族/异族判别（不参与生成训练） 回答「风格是否一致」，不替代生成像素分 本轮已训完（见第 6 节）

2.1 对照组怎么读（一问一表）

Baseline 口诀：讲 RSI 消融 → 底是 F0；讲 Support 消融 → 底是 F2；讲 Es 8 张平均 → 底是 F2 mean8（Δ 仍 ref8）。 不要把 F1 写成 F2/F3 的同条件对照组（1-shot vs ref8）。 Mode D 也不要和 Mode A 的 F1 比总分。

设计原则：每个对照表只回答一个问题；同表内 shot / Content / seed / 采样器必须一致；跨轴只能浏览，不能下结论。读图时看表头「对照组 = X」。

3. 推理条件是否一致？

一致、可并排对比的部分：同一测试 16 字体、同一 47 字符、同一真值、同一随机种子 3407、同一采样器设置、同一内容图。方法之间是完全配对的。
故意不同、读表时必须知道的部分：
  • 网络结构 / 条件化路径不同（这正是实验要隔离的处理）。
  • 检查点步数：官方微调与无结构迁移是 10 万步；近邻残差主表目前是 7.5 万步（8 万步已训完但未刷全量主表）；旧版支持特征是 8 万步。
  • 评测时看到的风格参考图张数不同（见下节）——官方微调三线是 1 张，近邻残差线是固定 8 张。
  • 公平对照请切 :8767 的 Mode A（1-shot）、Mode B（ref8） 或 Mode D（Es 平均，Δ 仍 ref8）；Mode C 禁止当总分榜。

4. 风格参考图：评测几张？训练随机还是固定？

风格参考来自该字体的汉字池。评测协议优先使用固定八字「永和书风骨韵天地」；但「喂进图像管线」与「近邻残差管线」用法不同。

新版支持特征

因此：近邻残差线与官方微调线在「评测可见参考图张数」上不完全对等（8 vs 1）。比较官方微调 ↔ 无结构迁移是公平的 1-shot；比较近邻残差 ↔ 旧版支持特征是同为 8 参考下的增量。

目前能看出的

  • 本数据微调后，像素诊断相对零样本有大幅改善。
  • 去掉结构迁移后略变差 → 结构迁移在本协议下有一点像素贡献，但幅度不大。
  • E12 上：8-ref 近邻残差 / 旧版支持 > 1-shot 官方微调（尤其 latin+digit mem_prob）。
  • 像素最好的官方微调，E12 mem 反而偏低 → 更说明「像素≠风格」。

现在不能下的结论

  • 不能说「已全面优于官方」——步数未对齐（7.5万 vs 10万）、单一种子、尚无人工盲测。
  • 不能把旧版支持特征成绩写成新版 F3b 成绩。
  • E12 是域内 scorer，不是开放世界字体鉴定器。

6. 风格评测器（本轮）

用途：在「给定字体参考 → 判断查询字形是否同族」的协议上打分；本轮已对 test16×47 各方法 pred 跑完生成器侧分数。

  • 风格编码器：验证 AUC 约 0.901（早停于 2250 步）。
  • 同族判别头：测试 ROC 约 0.937，PR 约 0.917。
  • 生成器打分：φ SC-R（与 ref8 原型余弦）+ membership 概率（温度缩放）。
  • 叙事边界：同数据域协议下的评分器，不是开放世界字体鉴定器。
