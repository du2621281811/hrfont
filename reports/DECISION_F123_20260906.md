## 1. 初始化：推荐 zero-init residual conv

### 方案

```
warped   = DeformConv(skip, offset)
skip_out = skip + zero_conv(warped - skip)
```

`zero_conv` 是 1×1 卷积，weight 与 bias 全零初始化。

### 为什么不用"严格 identity DCN init"

设计稿列的备选是把 DCN kernel 初始化成中心 identity、offset 输出置零。实测它**根本不成立**（`scripts/test_identity_safe_rsi.py`）：

```
[float32] max|with_RSI - raw_skip| = 0.000e+00   ← zero-conv residual
[float16] max|with_RSI - raw_skip| = 0.000e+00
zero-offset DeformConv:  max|DCN(skip,0) - skip| = 5.581e+00   ← 备选方案
```

零 offset 只是让 DCN 在规则网格上采样，它仍然要过那个 3×3 learned kernel。要让它等价，必须**同时**精确构造 identity kernel，而那又依赖 DeformConv 的 padding/边界/插值细节，fp16 下尤其脆弱。zero-conv 的等价性是代数恒等式，与算子实现和精度都无关。

### 为什么它同时"效果好"

这就是 ControlNet 的 zero-conv：在预训练主干上挂新模块的标准做法。相比标量 gate：

- 不是标量瓶颈，`zero_conv` 有完整的 C×C 容量，不会人为限制 RSI 能表达什么。
- step 0 时 `∂L/∂W_zero ≠ 0`（输入 `warped - skip` 非零），所以第一步就开始学，没有 gate 常见的冷启动停滞。
- 相比严格 identity DCN 的 delta-function kernel（容量全压在中心一格）是明显更好的起点。

### 归因优势

`rsi_gain = mean|zero_conv.weight|` 是一个**直接读数**，回答"这条臂到底用了多少 RSI"。它每 `log_interval` 写进 `train_log.jsonl`。如果 F2 的增益是真的，`rsi_gain` 应该随训练上升；如果它一直贴着 0 而指标却涨了，那增益来自别处，这个否定证据本身就有价值——不需要靠指标反推机制。

初始 `rsi_gain = 0`，parity gate 写 `parity_gate.json`。

## 3. 实现：一份代码，三条臂

`code/variants/cn2west_f123_rsi/`。三条臂共用同一个 `train.py` 路径，`--arm` 只切换一个因子：

| arm | rsi_source | support | 隔离的变量 |
|---|---|---|---|
| F1 | official `Ec(R[0])` | off | 新增 RSI 容量本身 |
| F2 | Δ | off | 相对 F1，只换 source |
| F3 | Δ | on, drop=.20 | 相对 F2，只加 Support |

`ARM_SPEC` 在 `main()` 里校验 `(rsi_source, support)` 与 `--arm` 一致，不符直接报错，防止 launcher 手滑。

### 修掉的旧失配

旧 Stage-A 的 `_structure_features` 在 official 分支**提前 return**，drop 只作用在 delta 分支上——这正是旧 E2 vs E2b 不 matched 的根因。新代码把 `--delta_drop` 换成 `--source_drop`，两个分支一视同仁。

同样地，`support_draw` 即使在 support=off 的臂上也照抽，否则 F2 与 F3 从第 1 步起 RNG 就分叉，后面每个 batch 的 CFG mask 都不同。

### 其它

- **父权重加载**：F0 没有 RSI 模块，`_load_parent` 用 `strict=False`，把新建的 key 写进 `parent_load_manifest.json`；任何非 RSI 的 missing/unexpected key 直接抛错。
- **Support**：`SupportAdapter` 的 token 只拼进 up-path cross-attention 的 context，MCA down-path 看到的 style map 不变，所以 F2↔F3 的差异只在一处。
- **cache**：F0 训练了 Es/Ec，所以 launcher 要求 `artifacts/f0/{es_spatial_f0,ec_multiscale_f0}`，缺失即 fail closed。**E1 的 cache 绑在 E1 encoder 上，不能复用。**
