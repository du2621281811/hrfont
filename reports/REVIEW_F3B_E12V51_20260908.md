## 1. F3b：六题审查

### 1.1 归因结构：组合可比，四因素不能拆清

**结论：F1→F2 的 Δ-source 主对比应保留；F2→F3 是旧 own-font support-enabled joint treatment；F2/F3→F3b 只能解释为系统包增量。20k style on/off + P0 + P1 不足以识别四因素的独立贡献，更不能识别全部交互。** 这不妨碍发表组合方法，但必须停止把 F3b 优势回填为旧 support 单因素优势。[`reports/ARMS_NARRATIVE_QKV_20260905.md:69`；`reports/DESIGN_F3B_20260908.md:12`、`:42`]

| 对比 | 可以识别 | 不能识别 |
|---|---|---|
| F1 vs F2，同端点、同配方 | official→Δ 条件源 treatment | 减 neutral、检索、same-char 各自必要性 |
| F2 vs F3，同端点、同配方 | 原 own-font support 与共同优化的总体效应 | 纯 adapter 容量效应；跨字体 support 效果 |
| F3b style-off vs style-on，20k | 在其余 F3b 配置固定时，多尺度 style 的条件效应 | 80k 最终效应；其他架构/支持来源下可迁移的主效应 |
| P0，固定 F3b checkpoint 更换 map | 该 checkpoint 对候选选择的推理期敏感性 | 训练时学会拓扑类比；map 训练必要性 |
| P1，相关/随机两臂同 F0 训 20k | 固定来源/注入/style 下，选字规则的短程训练效应 | 来源、注入位置及其与 map 的交互 |

上表是对设计 `:17` 的可识别性分析；原 F1/F2/F3 对比解释沿用三臂总表 `:49`–`:51`。即便所有短筛为阳性，也仍缺“跨字体 vs own-font、相同注入/选字”“解耦注入 vs 原注入、相同证据”等桥接对照；四因素完整二水平析因需要更多组合，9/25 前没有必要为此扩成全搜索。

**必须修补的 matched 契约：** 本次发现 F3b warmup 2k 对现网 F123 的 5k；推荐 F3b 回到现网 5k，其余四项仍按 PI 设计。若 PI 保留 2k，则把优化日程列为第五项实际变化，只称 system comparison，或增加相同配方 bridge。不得拿旧同名配置证明已经 matched。增加局部 token 还会消耗初始化和采样 RNG；“同 seed”不是同 draw，需独立可恢复模块 RNG、记录 episode/noise/timestep/CFG/source/support draw 并比对哈希。[`configs/f2_deltarsi_a_s3407.yaml:36`；`configs/f3_joint_ds_a_s3407.yaml:36`；`code/variants/cn2west_f123_rsi/FontDiffuser/train.py:567`；`.cursor/rules/hrfont-execution-spec.mdc:102`]

**20k 与 P0/P1 建议预注册：** style 两臂固定 mid-block，只变 style token；固定 20k endpoint，不各挑 best。P0 三变体建议明确为“原拓扑相关 / 按 target 固定置换的随机 / 低相关”，在相同字体邻域、同有效支持数、同 donor 配额、同噪声下比较；这三种是本报告建议，终版设计并未列出具体变体。P0 阴性不证明拓扑无效，只表示当前 checkpoint 未提供继续投资的信号；弱信号即不启动 P1，按 PI 顺序约束节省预算。P1 若启动必须两臂同 F0、同训练日程，不能只把训练过相关 map 的模型换成随机 map 后续训。[`reports/DESIGN_F3B_20260908.md:17`、`:50`；三臂文档短筛范式 `reports/ARMS_NARRATIVE_QKV_20260905.md:179`、`:181`]

### 1.2 双门候选池：先定义抽样单位，再审计 dropout

**结论：离线审计是 B0，不是可选可视化。** 风格门选字体、结构门选字符，二者并非同一空间里两个集合的普通交集。建议精确定义：

`P(f,R,c) = {(j,q): j∈Top10_α(f,R), j≠f, q∈Top16_topology(c), cache(j,q)有效}`。

完整覆盖时最多是 10×16=160 个 font–char 对，而不是 16 个；也可能实际意图是先对十字体同字池化、再抽 4–16 个“不同字符”。这两种分布不同，必须先定。若库完整且没有额外质量过滤，池应基本不会空；“双门”本身不是让池变空的理由。α top-10 是相对选择，不保证绝对风格相近；结构 top-16 也不是绝对语义相关的保证。[`reports/DESIGN_F3B_20260908.md:21`–`:25`；`.cursor/rules/hrfont-execution-spec.mdc:37`、`:49`]

**推荐实施语义（待 PI 批准）：** k_s 数的是不同 CN 字符；各字符在十邻域有效字体上等权汇聚，保留每字符一个 token，再供 cross-attention 使用。另一合法方案是抽 font–char 对并保留各 token，但要锁定 donor 配额，避免随机抽到某字体多次而形成意外非等权。不得把全部字符池化成一个 token 后仍声称 Q 在选择不同支持证据（见 §1.3）。均遵守“不按 α 额外加权”，只是澄清等权作用在哪一轴。[F3b `:23`、`:25`、`:30`；本报告的采样定义建议]

**离线审计最小输出：** 对每个 target char，在 train LOO 与 val 固定 R 下分别记录池大小均值/中位数/p5/min、空池率、<4/<8/<16 比例、独立 donor/字符数、拓扑分数与并列率、ref8 重合率；按 n-shot、脚本、大写/小写、字体类别交叉报告。列出空池原因（真实覆盖/缓存损坏/过滤），后两者不能静默伪装成鲁棒训练 dropout。冻结 N<k_s 时“不放回取 min(k_s,N)”等规则、有效 mask、推理 top-8 排序及 tie-break；不足 8 的样本单列。test 不用于调整这些规则。[F3b `:23`、`:44`、`:59`；exec-spec `:67`、`:71`、`:106`]

**dropout 联合分布推导：** 若 source-drop 为 0.25，support 先共享该 mask，再独立以 0.20 丢弃，且在 source 保留条件下池空概率为 e，则（暂不计 CFG）：

| Δ | support | 概率 |
|---|---|---|
| 有 | 有 | `0.75×0.80×(1−e)=0.60(1−e)` |
| 有 | 无 | `0.75×[0.20+0.80e]=0.15+0.60e` |
| 无 | 无 | `0.25` |
| 无 | 有 | `0` |

e=0 时 80k 个更新的期望比例对应 48k/12k/20k/0 个“更新等价量”，实际 drop 按样本抽，不能把它说成整 batch 类型。现有 F3 使用独立 source_draw/support_draw；若没有把 support 与 source 联锁，对应分布是 0.60/0.15/0.05/0.20。故 F3b 的共享 source mask 会移除 support-only 训练状态，也是旧新系统差异的一部分。[F3b `:21`、`:48`；`code/variants/cn2west_f123_rsi/FontDiffuser/train.py:569`、`:570`、`:575`]

**风险是条件性缺失，不是“80k 必然学坏”。** 空池若与脚本/难字强相关，模型可学到“难字=只有 Δ”，且跨字体 Δ 与 support 同源错误会相关放大；统一随机 support-drop 不能修复这种 missing-not-at-random。建议记录联合四格及按脚本的有效支持率、分组 loss、输出/梯度 norm；同时记录 CFG-drop 下 support 是否保留，训练与 CFG 推理流一致。按 PI 固定概率先观测，不事后按 test 调概率。[F3b `:21`、`:23`；exec-spec `:31`、`:45`；以上联合概率推导]

### 1.3 IP-Adapter 式注入：合理工程选择，但收益与稳定性未证

**结论：解耦 cross-attention 是有依据的条件通道，不是 F3b 新架构贡献；96×96、强 style 条件下收益属于待检验假设，不能接受“风险低/80k 一定吸收噪声”的断言。** 原 IP-Adapter 的解耦机制有先例，但原文冻结 diffusion 主干，不能把其结果直接当 F0-init 联合续训的稳定性证据。[L1；F3b `:30`–`:38`]

预期收益是减少 support 与 Δ 在同一 RSI source 流内的竞争，让 Q 按去噪位置读取支持；预期风险是 Ec 的空间均值已丢局部排列、支持字内容侵入目标字、跨字体风格平均化、多尺度 token 压过原 9-token 条件。将两条流分开不等于内容/风格统计独立。已有 F3 大写退化和字体级 9:7 胜负提示应按字体、大小写报告，而不能只看均值。[F3b `:25`、`:36`；`reports/RESULTS_COMPARE_20260907.md:8`、`:9`、`:39`；此处为机制推测，不是 F3b 结果]

**一个重要的数学陷阱：**若“等权池化”把全部 support 压成单一 K/V token，那么 `softmax(QKᵀ)=1`，attention 输出对 Q 的证据选择退化；多个相同 token 也一样。应保留不同字符/不同有效支持 token，或明确承认是 pooled conditioning。每字 Ec 的多尺度 spatial mean 不是空间 patch token：能保留某些风格统计，但不能据此保证局部拓扑对应。[推导依据：F3b `:25`、`:30` 的 attention 定义；旧 `_pool_ec`：`code/variants/cn2west_f123_rsi/FontDiffuser/train.py:214`]

**第二个 B0：局部 style cache。**现有冻结合同保存 3×3 style map；F3b 的 64–128 局部 token 必须来自真实较早空间层的离线特征，不能对 9-token 上采样后称“保留了丢失细节”。style encoder 已返回 `residual_features`，但本轮未证明所需层已经缓存。先锁定 layer、shape、R 维聚合、空间位置编码/无编码语义、SHA、缓存容量与训推 parity；不能用在线 Es 绕过 cache-only。[exec-spec `:38`、`:39`；F3b `:36`、`:44`；`code/variants/cn2west_f123_rsi/FontDiffuser/src/modules/style_encoder.py:428`–`:442`]

**随机初始化予以接受，不建议偷加 zero-init。**需要 step0/100/500/2k/5k 的 adapter输出/主流 norm 比、attention logits/entropy、梯度 norm、AMP overflow/NaN、loss 与身份退化日志；数值故障按预先定义的失败处置报告，不以临时 gain 调节隐藏失败。零支持时不仅输入清零，还要确保投影 bias/attention bias 不生成伪证据，整行有效 mask 和空集分支无 NaN。此处是缺失语义验证，不是防御性初始化。[F3b `:31`、`:48`；旧 support 空集处理 `train.py:228`–`:242`]

**20k 是否够？**够做固定 mid-block 的可训练性与早期非劣筛查，不够声称最优注入位置或最终风格提升。仅有 style on/off 两臂时不能同时筛位置，否则每臂换位置会混淆。推荐固定 mid-block、锁定 style 胜者后进行 80k 完整验证；无阳性则保持更简单配置，位置搜索移附录。[F3b `:30`、`:50`、`:60`]

### 1.4 错误风格污染：现方案不充分，独立人工审计先行

**结论：D-B3 的 φ_s2 在 T2 等门通过前不能给污染率定性或定阈值；通过之后也只能作为辅助邻域度量，不能自动等价“错误风格真值”。** T2 同族/异族判别不是跨族风格相容性或 top-K precision。D-B3 允许人工独立定义，当前最稳妥的是盲化设计师属性/兼容性判断，非再用 Es 自证。[`reports/DESIGN_E12_DELTA_20260907.md:56`、`:61`、`:164`；`reports/BANK_STYLE_NARRATIVE_20260906.md:26`；E12 v5.1 `:69`]

建议在 train/calib 范围预先冻结 rubric：笔重/对比度、衬线/端点、曲率/连笔、宽高重心、装饰性；至少两位独立评审判断“明显不相容/可相容/不确定”，分歧单列，不强迫所有异族为错误。几何属性可辅助，但不能只用 stroke width 或本方法拓扑表。按 ref style 类别与 n-shot 分层抽样，审计正确 top-10、随机 bank 和困难邻域；输出 top-1 wrong、wrong count/10、α 加权 wrong mass、实际等权 support wrong exposure、评审一致性及字体聚类 CI。两通道曝光量要分别统计，不把 α 质量当 support 权重。[F3b `:25`、`:26`；`reports/DESIGN_E12_DELTA_20260907.md:61`；此段为审计方案建议]

α 近均匀只证明“top-10 内加权≈等权”，不证明“选哪些邻居不重要”，也不证明污染低；旧 14%–47% 是分差假设例子，应用 9/7 实证 10.02%–10.21% 描述当前样本，且不能外推全部 R。[`reports/RESULTS_COMPARE_20260907.md:11`；`reports/BANK_STYLE_NARRATIVE_20260906.md:43`]

**E9 wrong-style swap 预注册模板（建议）：**

1. 假设 H1：固定正确 ref/content/noise，独立标注的不相容 donor 替换会使输出 family consistency/设计师匹配偏好下降；H0：平均无变化。用字体为聚类单位报告效应量、双侧 95% CI；H1 的方向提前冻结，不看结果改指标。
2. 固定 checkpoint，做“正确 Δ+正确 support / 错 Δ+正确 support / 正确 Δ+错 support / 二者皆错”四格；共享 α 是主方法，单通道 swap 是明确标记的机制干预，不偷偷改主方法。Δ 保持同目标字符，support 保持选字/k/donor 数，才能隔离风格而非内容缺失。
3. 每尺度 Δ 做原 E9 RMS 匹配，`eps=1e−8`、clip=[.25,4]；support 在预先固定的特征/投影层匹配 RMS，记录 norm/裁剪/排除率。控制幅度不消除方向及分布 shift，仍须声明 OOD intervention。
4. 主要终点为盲法 family-match；过门 φ_s2 辅助，ID/quality 同报。若两者同坏且 ID 也崩，不能专归因风格；若 swap 无影响，可能 support 被忽略、错风格定义无效或尺子不敏感，不可直接宣称鲁棒。四格交互只在固定 checkpoint 上解释，不当训练期因果交互。

依据：F3b `:26`；exec-spec `:107`、`:120`；`reports/IDEA_ICLR_SCORE_20260907.md:99`、`:100`。正/错 support 的选择和假设应先冻结于 val/calib，不能从 test 失败图挑最显著反例。

### 1.5 叙事一致性：三面是类比，不是三个独立机制

## 2. E12 v5.1：六题审查

### 2.1 目标操作化：可以测族相容性，不能直接测全部合理性

**结论：membership 是“参考语境下家族一致性”的可操作代理，不是设计合理性的充分定义。SupCon 修同族假负例是正确方向，BCE 可学 pairwise verification，温度校准校正置信度；三者合用不自动获得设计偏好或拒绝伪影的能力。** 正例同族、负例异 lineage 的监督仍在定义 family discrimination；与旧三轴口径相容的写法是“合理性中的 family-consistency 轴”。[E12 v5.1 `:11`、`:26`、`:47`、`:52`；`reports/DESIGN_E12_DELTA_20260907.md:78`–`:86`；L7、L8]

具体失效模式与诊断建议：

| 失效模式 | T2/附加诊断如何识别 | 证据边界 |
|---|---|---|
| 记住训练家族身份、weight 或渲染来源 | 外层完整 lineage 留出；同 weight/serif/宽高的 hard negatives；分族/属性报告 | 严格 CV 可排除训练族记忆，不能排除泛化的粗属性捷径 |
| 家族标签不等于跨脚本设计一致 | 审计字体 Latin 借用/复制、同族异脚本人工相容性；允许 ambiguous 标记 | 两异族可能同样合理，不能一律视为语义“坏字” |
| 单候选质量分类，忽略 R | 同一 P 配正确/错误/空 ref；ref permutation；同候选配对 score 差 | wrong-ref 显著是必要证据之一，不是全部效度 |
| 只认真实渲染，对生成伪影高置信 | 冻结后用独立盲评方法输出验证预测力；训练/选 evaluator 不看方法输出 | T1–T4 只在真字体通过不能证明 generated-domain calibration |
| 把字符身份误作风格、对细节不敏感 | script/大小写/digits 分层、字符留出诊断、对缺笔/多笔/重音变化的身份护栏 | membership 输入无目标字符标签，无法独自判断 P 是否就是指定 c |

依据：旧 T2 根因与字重双峰 `reports/E12_OPTIMIZATION_PLAN_20260907.md:11`、`:24`、`:39`；E12 v5.1 `:26`、`:61`、`:66`。建议为未来验证方案，不声称上述诊断已跑。

**必须说清的 T2 限制：** 若正负仍完全由同/异族给定，即便严格 CV 达到 0.95，也只能证明对未见家族的参考条件验证；不能用这个 T2 自己区分“学到了族相容性”与“学到了设计合理性”，因为标签没有提供该区别。需要独立的人类 family-match 与 design-plausibility 两种题、相同候选错 ref、属性匹配负例及伪影反事实共同验证。[`reports/DESIGN_E12_DELTA_20260907.md:76`–`:86`；E12 v5.1 `:25`–`:28`]

**一 encoder 与 CV 的正确边界（B0）：**

- 可接受：“同一训练 seed，外层每 fold 重新拟合所有接触外部池标签/图像的 encoder、projection、聚合器、W/BCE；内层选骨干/超参、拟合温度；外层族完全不进拟合。最终协议冻结后，外部全池重训一个部署 encoder。”单 seed 不等于只允许拟合一次。
- 不可接受：“全池训一次 encoder，然后留一个 family 的 query 测分/只重训 head”，因为 encoder 已见该族。这只能叫 seen-family/conditional-head probe。
- 若坚持整个开发期只能训练一个 encoder，从零 R18 无法同时提供严格 LOFO；必须选择真实独立且从未用来适配外部池的 frozen backbone，并把 CV 约束到所有可学习 head，或承认没有未见族 CV。更推荐 PI 批准 grouped K-fold，见 §2.4–§2.5。

这是从学习依赖关系推出的隔离要求；旧优化 v2 `:160` 的“外部独立性保证泛化”表述过强，不能覆盖 `:165` 要求的实际留族验证。四路选赢家还需 nested CV 或事前锁定开发/确认集合；选出最高 CV 再把同一分数当无选择偏差的验收不成立。[E12 v5.1 `:9`、`:28`、`:32`、`:59`；L9]

**打分/门的额外缺口：** `zPᵀWzR` 可以训练成好 membership 排名，却不保证原始 cosine SC-R/SC-Gap 同样有效；三个输出“同源”不等于测量等价，须各自对照。明确是联合 `SupCon+BCE` 还是先 encoder 后冻结 head、λ 与正则系数、正负比例、ref mask、可变 k 下每族均衡，以及不把 P 本身加入 R/G。训练 k≥2 与生成器训练 n≥1 不完全一致；正式 ref8 可做主范围，n=1 必须另标外推/验证。[E12 v5.1 `:25`、`:47`–`:53`、`:66`；exec-spec `:50`]

**门限不是只保留数字：** 当前 T3=0.977 是 62-way ID accuracy，不是 membership AUC；旧 T1 是同族跨脚本 cosine 中位数，不是 CN↔Latin 二分类“判定一致率”。建议保留 T1-legacy/T2-legacy/T3-ID，新增 T2-membership-CV 与 T3-membership-calibration；冻结新 estimand 并与历史并报。不放宽 0.90/0.85，但不能把更换任务称为门完全不变。“无判定阈值”又使新 T1 的“判定”更需数学定义。[`scripts/eval_framework/self_tests.py:22`–`:29`；E12 v5.1 `:58`–`:68`；`reports/E12_OPTIMIZATION_PLAN_20260907.md:18`、`:39`]

### 2.2 GT 通道：w 冻结不等于 GT-free

**结论：主分必须严格是 `p_mem(P|R)`；`s_final=w·s(P|R)+(1−w)·sim(P,G)` 只要 w≠1，测试计算就需要 G，因此是 GT-assisted 次要终点。** 在校准集上选择 w 本身不是测试泄漏，但把含 G 的分数叫主 GT-free 合理性会构成边界失真。若只在校准集计算该融合分而主测试不用，应删除“final”语义，明确只是校准诊断。[E12 v5.1 `:13`、`:48`]

**w 如何定（建议而非已定事实）：**最简推荐主分 w=1，GT 融合留附录；若研究融合，用外部 lineage 的内层 calibration pairs 与预先规定标签，先将 membership 概率和 GT 相似度都映射到可比较尺度，再在固定小网格（如 0/0.25/0.5/0.75/1）按 family-macro Brier/NLL 选 w；温度与相似度映射也只能在内层拟合。外层一次性报告，部署前由 pooled out-of-fold 校准方案冻结参数。不能直接把 logit 与 cosine 相加当概率，不能用 test 方法排名或 PI 喜欢哪个结果定 w。[E12 v5.1 `:47`–`:48`；L8；本报告校准设计建议]

**注意标签问题：** 若 G 是同族另一个不同字符，它不是候选字符的 pixel GT，宜称 G_aux；其角色是额外同族证据。若是同字符真实 GT，则融合分更接近 fidelity-assisted score，二者需要分别定义。训练 G 正锚/一致性只能取外层训练族，不能把被留出家族图像经“增强”注入。即便 G 仅训练可用，也需一项无 G 增强的开发对照，判断额外监督是否只提升族识别。[E12 v5.1 `:25`–`:27`、`:48`]

**calib16 陷阱：** repo 的 calib16 来自 train228，不是外部独立池。如果用它拟合 E12 温度、w 或选择 evaluator，就违反 v5.1“永不接触 A/260”的参数拟合边界；本报告推荐使用名字明确不同的 `external_calibration_families`。calib16 可用于生成器干预阈值设计，但 evaluator 参数不由其更新。若 PI 有意放开，必须改独立性声明，不能静默称仍完全隔离。[`.cursor/rules/hrfont-execution-spec.mdc:123`；E12 v5.1 `:12`；旧 membership 校准混入 test 的代码见 `train_membership.py:32`、`:38`]

报告协议至少分三栏：①GT-free membership 主分；②SC-R/SC-Gap 辅助嵌入指标；③明确含 GT 的辅助融合/像素指标；另列身份、质量、人评。所有方法共同冻结 evaluator、温度、w、pair manifest/SHA。GT positive control 是一种合理实现，不是绝对上界；训练真字体平衡正负得到的概率也不是生成字真实“合理率”，应同时报 Brier/ECE/NLL/reliability curves、正负采样先验和域外失校准限制。[E12 v5.1 `:67`–`:69`；exec-spec `:97`；L8]

### 2.3 范围对齐：295 方向正确，覆盖与渲染仍需审计

**结论：不能从“≥60 CJK 字型”推断“每脚本都有≥60 独立家族”。** 清单算术是 10+52+27+83+86+37=295；27 指 latin_ext，不是全部假名/注音。字体文件覆盖 CJK/Unicode block 不保证这 295 个码点全有可用 glyph；CN ref8 也要覆盖。Noto 完整 CJK 版本确实覆盖多个相关 block，但语言子集版本和独立作者字体不能据此外推。[E12 v5.1 `:17`–`:20`；L10]

**现实性预估（定性，不冒充实测覆盖率）：**基础 Latin/digits 最可能成为较大公共池；27 个扩展拉丁含拼音变音字，应逐码点核验；kana 在日文字体/完整泛 CJK 中较有希望，bopomofo 更依赖繁中字库/完整版本。达到“60 个同时拥有 CN-ref8 与全部295且 lineage 独立”的池是高风险目标，特别是许多可用版本共享字形来源。本次未下载并审计新池，不给没有分母依据的 70%/90% 数字。[E12 v5.1 `:19`；L10；`reports/E12_OPTIMIZATION_PLAN_20260907.md:27`]

### 2.5 统计设计：单 seed 可披露，CV/CI 不能替代 seed 稳定性

**结论：单 seed 本身不是必拒，但在已知 v4 seed 差异、且 evaluator 决定方法排名时，很可能成为审稿追问。没有依据给“被攻击概率80%”之类数字。** 旧 v4 同五族 T2=0.791/0.795/0.725，seed SD≈0.039；它是风险信号，不是新算法方差估计。训练 seed 固定与字体重采样 CI 回答不同问题。[`reports/E12_OPTIMIZATION_PLAN_20260907.md:9`、`:20`；E12 v5.1 `:9`]

**建议冻结 estimand：**对每外层留出族 f，固定 ref8，逐脚本/字符构造真实同族正例和预先定义的跨 lineage 负例；同字符正负平衡，负例在候选族间均匀或按预冻结难度分层。先求 `AUC_f`（半权处理 ties），再 `macro_AUC=(1/F)Σ AUC_f`。报告随机负例与属性匹配 hard-negative 诊断，旧 pooled cosine AUC 并行保留。score、负例候选池、script 权重、ref 集、fold 都必须锁定；不要把换 scorer/换负例带来的难度变化称为纯 SupCon 提升。[优化计划 `:18`、`:24`、`:143`；E12 v5.1 `:28`、`:47`、`:59`]

**cluster bootstrap：**以 lineage 而非 glyph 为单位，对配对方法差共同重采样；若同一个 negative/ref family 被大量复用，query/ref 两端存在交叉聚类，优先重采样 family 节点后重建 pair 权重，或另做双向 cluster sensitivity。跨折共享训练集也使外层预测相关；仅对固定 out-of-fold scores bootstrap 的 CI 是“固定训练流程实现下、对评测家族采样”的近似区间，不覆盖重新训练、骨干搜索或 seed 的全部不确定性。报告 CI 的条件性，不把 60 折当 60 个独立模型实验。[优化计划 `:33`；E12 v5.1 `:28`、`:59`；本报告统计依赖分析]

**0.90 / CI≥0.85 是否现实？**是可尝试的质量门，不是可从“扩到60族”推出的预计结果。SupCon 消除假负例、扩字符轴有直接机制动机；更多训练族可能改善表示，但更广泛/更难的测试族与困难负例也可能拉低 macro AUC。相同总体、相同模型、同难度下增加独立族主要提高精度，不把0.79自动抬到0.90；当前 v4 的0.79是在26总族中的5个固定测试族、pooled cosine 口径，不能称“26-family macro baseline”。[优化计划 `:5`、`:18`、`:20`、`:139`；E12 v5.1 `:59`、`:62`]

**规划性算术示例：**若60个族 AUC 可近似独立、SD=0.20，宏均值0.90的正态近似下界约 `0.90−1.96×0.20/√60≈0.849`，恰贴门；SD=0.10 时约0.875。它不是 bootstrap 预测，实际配对依赖/小子池/选择会更复杂；说明达主均值也不保证过 CI，必须先看 per-family 分布。禁止为过门删除低分族或降低门；coverage 排除必须在看分数前冻结。[推导，假设明确；门取自 E12 v5.1 `:59`]

**temperature scaling 不能救 T2 排名。** 单一正温度是 logit 的严格单调变换，因此理论上不改变同一集合 AUC，只改校准；跨折不同温度可能影响 pooled ranking，macro-family 更应定义清楚。BCE AUC≥0.90也不代表概率校准良好，T3须同时报 Brier/NLL/ECE/可靠性曲线，不能再把 AUC 当校准唯一门。[L8；`scripts/eval_framework/train_membership.py:18`–`:24`；E12 v5.1 `:60`]

**备用答辩话术：**“本版固定训练 seed，以预注册 lineage CV 估计外部家族泛化；CI 反映评测家族变异，不反映优化随机性。所有生成方法使用同一冻结评分器，主结论还由独立设计师盲评验证；不声称 evaluator 训练稳定性已全面建立。”若接近门、子池失效或方法排序依赖 scorer，建议请求补第二 seed，作为敏感性完整并报，不能挑更好的 seed 过门。若 PI 不批准，保留单 seed 限制，不虚构方差。[E12 v5.1 `:9`、`:68`；idea 评估 `:211`、`:219`]

**最终评语：**两个方案都有研究价值，但目前最有价值的提升不是“更复杂”，而是“可证伪且交付得出”。F3b可作为完整系统候选，Δ主张依赖现有核心对比；E12可作为独立评测组件候选，合理性主张依赖真实未见族验证和盲法设计师外部效度。无阳性证据就降低claim，不降低门限，不把计划写成结果。[F3b `:4`；E12 v5.1 `:10`、`:68`、`:69`；idea评估 `:335`–`:339`]
