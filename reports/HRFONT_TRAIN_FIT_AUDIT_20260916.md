# HRFont训练集风格欠拟合：设计、实现与冻结权重诊断

2026-09-16。Git main核对为4f9eebf3390ce14b4f761285806ac30f1994aad5。检查F0/G0父训练器、F2/G缓存条件实现、I1–I5实现、训练记录及冻结I5@4k权重。没有重新训练每个历史F/G模型，不能把I5局部支路诊断当作所有历史模型的同一个根因。I5仍安全暂停；无训练、无线上代码/权重修改。本地诊断入口：[diagnostics_20260916_underfit.py](diagnostics_20260916_underfit.py)。

## 结论

问题不能只归结为复杂字体太少。证据最强的是：I5的新局部风格信息已经有一定表达能力，但进入生成器的实际影响很弱；过往预检未真正证明完整扩散过程可过拟合；评测板还混入了清洗排除的字体—字符组合。提高复杂样本曝光值得验证，但应在修复验证口径、打通风格条件利用之后做可归因的对照。

训练字体在固定参考条件下仍不够保真，值得优先排查。但“训练字体出现过”“目标字符在清洗后训练集中”“完全相同的参考组合出现过”“所有噪声时间步都训练充分”并不等价。合理最低要求是小型已见字体/目标集能在完整生成过程中恢复明显、正确的风格；不能只看噪声MSE下降。

## 2. 已实测：I5新局部风格路径贡献很弱

`scripts/hrfont_i.py:83–96`的生成器路径为：

```
old_attention + local_gain × ramp × local_attention
                   ↑
       自由学习标量，初始化0.01，可趋近0

local_tokens → InkReadout → TC loss
```

TC loss不经过local_gain。因此局部Reader/TC读出可以得到梯度、减小自己的误差，而生成器同时把局部分支压小。这不是梯度完全断开，而是监督和实际使用之间存在可绕过的路径。旧global9路径一直保留，并未随局部Reader成熟而退场。

执行机读取EMA标量：I1约0.0008、I2约0.0495、I3约0.0014、I4约0.0030；I5@4k为0.000611814。不能单凭系数大小判断作用，因为token幅度也会变化，因此额外测了实际激活和最终图像。

I5@4k，6个确认细节训练样本（跨三语种），5个固定噪声时间步。下表为各up-attention模块的`||gain×local||/||old||`平均，不是全网络输出占比：

|t|实际局部/旧支路幅度|噪声MSE|从带噪GT反推的原始x0 L1|
|---|---:|---:|---:|
|50|0.240%|0.006441|0.001148|
|250|0.220%|0.003139|0.003391|
|500|0.202%|0.002013|0.008953|
|750|0.175%|0.001325|0.035048|
|950|0.154%|0.000410|0.153016|

交换不同字体参考（保持目标content/Delta不变）时，TC读出像素L1变化0.087–0.241，6例TC细节误差均变差；t950反推x0平均变化0.14285。说明整体ref通道不是无信息。关闭局部支路则t950 x0变化仅0.001007。后者只有约前者的0.7%，但这是这6例/该t上的干预量比较，不是普遍因果贡献分解。

完整DPM生成再验证3例：关闭局部支路后的最终图像L1变化分别0.000506、0.000604、0.000878（像素范围0–1）。这一实测足以确认当前I5局部通路影响很弱，不能据此断言全部style或Delta无效。

## 3. 确定的验证设计缺口：旧overfit固定了噪声、t和drop mask

`scripts/train_i56.py:206–220`：overfit时key=0，循环每步重新用相同seed初始化RNG，随后抽refs、source-drop、CFG、noise和t。因此同一个固定样本始终在相同噪声/时间步上训练，部分样本还始终处于同一drop状态。正式训练key随attempt变化，没有这个问题。

旧预检只跑304步：TC误差下降18.26%，完整采样误差下降1.72%，16例中9例改善；local开关只要求像素变化>1e-5。它验证了代码能优化和路径非严格零，不代表学会完整条件分布或接近过拟合。前10步loss中位数0.1622→末10步0.03779，也不能替代完整生成质量验证。

应修正为：固定真实图像和参考列表，但每步重新抽独立noise/t；先关掉CFG/source-drop等正则，再分阶段恢复；从纯噪声生成，分别比较raw与EMA。小样本验收同时看风格复现、前景/内部白区/边缘误差、正确ref优于错ref，而不是仅要求loss有下降。

## 4. 高噪声阶段监督与显示loss不对齐：强假设，非已证明唯一根因

DDPM epsilon预测可写成`L_eps = SNR(t) × ||x0_hat-x0||²`，这里x0坐标为[-1,1]。低噪声输入中本来已有GT风格，网络可以主要去噪而少用ref；高噪声才更需要条件，但相同x0误差对应的epsilon误差很小。实测t950噪声MSE仅0.000410时，原始x0 L1已达0.1530。

I3–I5的图像细节loss还乘alpha_bar（`i56_components.py:58–61`）。t950 alpha_bar=0.001889；链式梯度对epsilon的权重随sqrt(alpha_bar×(1-alpha_bar))变化，因此很高/很低噪声处都弱。这个稳定化选择有理由，但不能仅凭全时间平均梯度校准断言关键阶段的风格监督充足。

旧VGG路径通过scheduler的clip_sample和reNormalize clamp；越界像素经过clip后梯度为0。探针中原始x0越界像素很多，不过白底本就在边界，不能把越界占比直接解释成前景失败或唯一根因。应按前景/细节区域及SNR分桶测梯度，再决定有界重加权；不要直接去掉全部时间权重放大高噪声梯度。

I5末批总loss0.04404中：epsilon约0.002412，加权VGG约0.032167，TC约0.008179，输出细节约0.000854，偏移正则约0.000425。标量大小不等于梯度占比，但说明“总loss下降”不能代替“生成风格改善”。

## 6. 共用实现风险与已排除项

- F/G缓存式下游和I旧主路仍依赖ref均值3×3 Es map/9tokens；I有高分辨率在线Reader，并非“Es冻结导致完全无法学习”，但I5实测Reader生成注入很弱，新增容量未成为主要风格来源。G0b本身联合训练Es/Ec，不能笼统说所有G都冻结编码器。
- 共用StyleEncoder.forward末尾block已经在循环中调用，随后又执行`self.blocks[-1](h)`（line432–437），包含重复InstanceNorm/ReLU/1×1conv。重复执行是代码事实，是否导致风格受损尚未做归因；旧权重/缓存已经适应该语义，不能直接删一行后复用全部缓存宣称修复。
- 核对I5冻结快照与所审Git：hrfont_i.py、train_i56.py、i_runtime.py、StyleEncoder的SHA一致。读取的是实际执行实现，不是只看方案文档。
- 数据loader按同字体抽中文ref与目标；TC在线Reader在可求导forward内，条件构建的no_grad不包住Reader；raw/EMA正确加载路径存在；当前日志没有AMP跳步/DDP分歧/非有限值。未发现可支持“全部ref配错”或“TC完全没梯度”的证据。
- Delta不是首要嫌疑：I0/G0b本身无RSI-Delta仍有保真不足；I5 ref交换诊断保持Delta不变仍有明显响应。Delta质量可能影响形态，但增加复杂采样时不应同时再重做Delta，造成不可归因。

## 7. 复杂风格占主导是否能解决

有机会改善模型偏向普通字体的问题，但不能保证解决当前弱条件使用和欠拟合。当前I5有效细节组比例只约10%–15%；30%额外分支不是30%细节样本。现有3倍cap使理论稳定上限约10.76%/11.17%/16.15%。即使只把extra_fraction调到0.7，也不能在这套cap下成为多数。

若目标为各语种60%确认细节组，仅从总量看所需cap下界约16.7/16.1/11.1倍；因此应改成明确的分层quota，而不是沿用3倍cap却宣称60%。需要扩大可核对的字体覆盖、保留约30%–40%普通字体，防止把22个确认字体—语种组反复背下来。复杂度应按字体—语种标签配合字符可表达性分层，不把所有U/一类简单字符误标成复杂字形。

旧overfit预检已经只从确认细节组抽样，即100%复杂组，但其固定noise/t和弱验收使它不构成对高比例采样方案的充分检验。

## 8. 建议的下一步，尚未执行

1. **先修验证，不改故事**：clean pair过滤、正确I0 unconditional、固定小数据但每步随机noise/t；正式结果保持历史归档，新增协议版本。
2. **小样本可拟合性检查**：例如8个已核对字体×4个目标字，覆盖不同字重/笔端/空心/断笔与三语种；固定refs、关闭drop，先做1000–2000成功更新，达不到明显高保真就不放大全集。
3. **只改使用接口作对照**：保持Delta与Reader/TC架构，比较原注入和有明确非零强度的归一化局部注入；旧global9逐步退让，不再允许一个自由标量把整条新风格支路压到近零。不能在旧检查点推理时直接把gain从0.0006改成1当成修复，需要从共同起点受控训练。
4. **在可拟合接口上比较采样**：同配置/同预算，当前曝光vs60%–70%确认复杂风格quota，普通字体作剩余覆盖；此时才回答数据主导比例是否带来额外收益。
5. **如果高比例仍无效**：按SNR分桶测生成loss传回Reader/UNet的梯度，优先处理高噪声风格监督；只有当目标图oracle条件明显优于真实中文ref时，再把主要矛头转向跨文字表征能力。不要先增加新TC/矢量分支。

上述是review方案，不是已派发实验，也不改动当前I5/I6授权或4k门槛。训练检查采用ml-training-recipes技能中的小批次过拟合、训练/推理一致性与梯度诊断流程。
