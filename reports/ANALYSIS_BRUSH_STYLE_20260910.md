## 0. 结论与证据等级

1. **先补 ref 局部证据，不先改 Δ。**Es 的多尺度 `residual_features` 确实返回，却没有进入现有 Es cache 或主生成接口；这是明确的实现缺口。中层适合优先诊断连笔、收笔与轮廓，早层适合诊断飞白等细纹理；“适合”不是已证实可恢复。见 §1、§2。
2. **P 修复 ref 轴聚合，不修复空间/早层信息缺失。**每个 h 又池化掉该 ref 的 3×3 空间轴，能保留 ref 间差异，但没有新增早层观测。应继续完成 P 的预定评测；若局部属性不足，接独立 P+local 臂，而非中途改正在跑的臂。见 §2.4。
3. **特效几何可以存在于 Δ，但“库里有”不等于“Δ 有”，更不等于“RSI 能画”。**必须逐段确认同族 donor 入选、特效在 Ec 中可辨、混合后仍存、offset/warp 消费及输出响应。每字设计仍是库条件下的偏好，而非 ref8 唯一确定的真相。见 §2.3、§3。
4. **Q2 不能裁为“Δ 无罪、Es 已坏”。**Mode D 的 Δ 固定，改变 Es 后宽窄粗细仍变，直接说明 Es 路径仍影响几何；它既不能证明 Δ 正常，也不能证明 Δ 压制不存在。优先归因为“细粒度 ref 条件保留/利用不足”，以固定 checkpoint 的结构源交叉干预判决。见 §4。

## 1. 实际信息流：哪里保留，哪里丢弃

### 1.1 Es 输出不是只有 3×3，但生成路径只拿了末端

在 96×96、`G_ch=64` 时，架构 down 输出为 48/24/12/6/3，通道 64/128/256/512/1024（`V/src/modules/style_encoder.py:293`、`:321`）。`save_featrues=[0,1,2,3,4]`，forward 用 `save_featrues[:-1]` 保存，因此实际列表是：

| 返回项 | 形状（省 batch） | 解释及本轮优先用途 |
|---|---|---|
| `residual_features[0]` | 3×96×96 | **原输入 RGB**，不是首段 64-channel 特征 |
| `residual_features[1]` | 64×48×48 | 第一 down 输出，局部边缘/纹理候选；已做过一次平均下采样 |
| `residual_features[2]` | 128×24×24 | 第二 down 输出，端点、笔画邻接与局部形状候选 |
| `residual_features[3]` | 256×12×12 | 第三 down 输出，R-L128 的候选源 |
| `residual_features[4]` | 512×6×6 | 第四 down 输出，更粗空间候选 |
| `style_emd` | 1024×3×3 | 末端处理后的 spatial map，不是列表中某个 3×3 项 |
| pooled `h` | 1024 | `AdaptiveAvgPool2d(1)` 后展平；cache 还做 L2 normalize |

以上为代码推导，非本次实测张量；索引依据 `V/src/modules/style_encoder.py:354`、`:392`、`:428`。不要把 `residual_features[0]` 误接成 64×48×48。

**丢弃位置已确认：**`scripts/hrfont_build_e1_caches.py:115` 中 `spatial, pooled, _ = model(images)`，只存末端 spatial 和归一化 pooled；`scripts/hrfont_feature_cache.py:18` 也只定义这两种 Es shape。在线 fallback `V/src/model.py:41` 同样 `style_img_feature, _, _`，丢弃 pooled 和全部中层。当前 cache-only 路径禁止 encoder 在线 forward（`V/train.py:584`），所以“Es 已经返回”不等于训练能直接读到；新增层需要离线缓存及 manifest，不是取一个已存字段即可。缓存构建器虽名含 e1，当前 F 系列应使用 F0 权重/cache，不能混用 E1（`reports/F123_STATUS_20260907.md:51`）。

旧生成 style 为 `mean_ref(spatial)`，而逐 ref normalized h 用于检索（`V/train.py:133`）。末端 map 在 `V/src/model.py:49` 展成9 token；四维 map 另送 MCA，`V/src/modules/unet_blocks.py:227` 是 **mid MCA 的 style attention**，不是 up-path P 接口；down 同类消费见该文件 `:341`。up-path 接 `encoder_hidden_states[2]`（`V/src/modules/unet.py:283`），support 在 `V/src/model.py:63` 拼入这一段。定位注入点时必须区分这三处。

### 1.2 不可把网格尺寸直接当频率上限

**[推断]**3×3×1024 不等于只有9个灰度采样；通道可编码局部纹理统计、类别或某种端点存在性。因而“3×3/12×12 绝对装不下任何1–3px信息”不是由 shape 可推出的结论。更准确的是：反复卷积/平均下采样、末端处理和全局池化不保证保留原始纹理的精确位置、相位与每个局部事件；空间尺寸也不是感受野大小（`V/src/modules/style_encoder.py:385`；旧报告 `reports/SOLUTION_STYLE_WEAKNESS_20260909.md:33`）。

确定的单向关系是：`h = pool(style_emd)`，仅靠 h 无法恢复在 `style_emd` 中已完全不可辨的信息；但每-ref h 序列可能比 **跨-ref均值** 更好，因为它保留另一条轴。不能用该关系提前判 P 必败，也不能用 P 的成功证明早层纹理已完整保留。是否仍有可用信息必须分为“特征可辨”“接口可传”“生成器利用”三个实验问题。

## 2. Q1：四层分析与最小改动

### 2.1 第一层——笔画几何：连笔、顿点、空心轮廓

**特征本质。**连笔是笔画邻接/连通关系的变化；顿点涉及端点的宽度、局部曲率与墨团形态；空心是内外轮廓及孔洞。它们不是统一的“高频纹理”：较大连桥、空心轮廓可以跨多个像素，拓扑也不能仅用频带定义。某种连笔原则可由 refs 展示，但具体目标字符何处连、哪里留孔，可能仍落入第三层的不可辨识性。

**理论承载通道。**优先看 Es `[2]` 的24×24与 `[3]` 的12×12，必要时上溯 `[1]` 48×48；它们比末端更有空间索引。当前 ref 的 Ec 同样含48/24/12多尺度几何（`scripts/hrfont_feature_cache.py:11`）。两者均须控制中文内容混杂：同位置的中文部件不等于拉丁目标的同位置笔触。

**现有缺口。**Es 中层没有进入生成；h 更是全局摘要。**F1 official RSI 已经是 `Ec(R[0])`**（`V/train.py:169`），并非“从未尝试 ref Ec”。它是把单个中文 ref 的绝对结构特征作为 offset 条件，不是把所有 ref 的局部笔触作为可寻址 style 证据。把 ref Ec 接回同一个 RSI 接口只是换回 official 类结构源，不构成新的局部风格方案。当前 own-font support 也非同一方案：先空间池化再映射 token，不能视作保留了 ref Ec 原始几何图（`V/train.py:225`；P 定义 `reports/DESIGN_F2P_F3BP_20260910.md:11`）。

**最小修改候选。**优先沿旧 R-L128：每 ref Es `[3]` 12×12→4×4，16个256维 token，经一个共享 Linear(256,1024)，ref8 共128个，附加到 **P 的 up style context**，不改 Δ、不改 down map、不新增 gate。称为 **P+L128**，不是把 P 换回 global9 的旧 R-L128。先验证 `[3]` 与池化后的4×4仍能区分属性；若仅24×24/48×48有信号，则另批相应层/局部采样版本，不硬套4×4。具体门槛与继承关系见 §2.4。

ref Ec 局部 token 是**次选替代源**：仅用同 ref8、固定局部预算、独立投影至既有 style context；不把未对齐中文 map 加到目标 Ec 上，也不把它混进 Δ 的 donor 字符轴。只有 Es 各层无有效信号而 Ec 同字跨字体诊断阳性，才考虑等 token/近似容量的 Es-local 对 Ec-local 控制。不是现在同时加两个分支。

**预期收益与风险。**有机会改善收笔、粗细对比、局部连断与轮廓；不是保证空心1。风险是4×4池化再次损失信息、中文部件复制、context 竞争和生成错误连桥。无位置编码的局部 token 更像局部描述集合，不能声称保留了 ref 全局拓扑邻接；其 token 的感受野可能提供局部关系，但须用连通/身份盲评验证。上述方案依据旧 R-L128 的约束与风险（`reports/SOLUTION_STYLE_WEAKNESS_20260909.md:91`、`:104`、`:114`、`:185`），不是已验收实现。

### 2.2 第二层——像素纹理：毛笔飞白、干刷、细颗粒

**特征本质。**关注原生96图上可见的1–3px笔画内空隙、沿笔势的明暗不连续，而不是字体整体变细或抗锯齿边缘。应把笔画内部纹理与轮廓锯齿/采样噪声分开；GT 是否真的含可迁移纹理，逐字体、逐目标字符标注，不只看“毛笔字体”名称。

**理论承载通道。**Es 第一 down 的64×48×48是最小外部依赖候选，但它也经过下采样，1px事件仍可能损失。必要时诊断第一 block 内下采样前 activation 或原输入；后者是新增缓存抓取位置，不是已有64×48的别名。相较之下，12×12可能携带纹理统计，却不应当作像素细节地图。接口应保留局部 descriptor，而不是把48×48再次全图平均成一个向量。

**外部 VGG19 核对。**`external_eval/get_stroke_embedding/models.py:11` 默认抽层索引3/8/17/26，返回四段 feature maps；从原生96输入推导其空间为96/48/24/12。它不是可直接拿来就可信的 ImageNet evaluator：构造是 `weights=None`，再从公司 checkpoint 加载 extractor 和 adapter（同文件 `:15`、`:63`）。本地 `weights/` 仅见说明文件，未验证权重可用、训练域、授权及西文有效性，故本轮不能实际跑该诊断。

特别注意两个再压缩点：adapter 对各层做空间均值（同文件 `:49`）；API 的 `style_token` 最后还对4 token 求均值，`pooled_feature` 也全局池化（`:83`）。因此**公司 API 最终 embedding 不是高分辨率纹理通道**。诊断应读取早期 maps/局部统计，而不是只看其整体 cosine。默认 API `decode_image(size=256)` 会 resize（`external_eval/get_stroke_embedding/app.py:45`、`:62`）；需离线直接以96 RGB调用 extractor，或显式保证96输入，不能把256插值结果当新增真细节。

**最小修改候选。**先不接外部模型、不加频域 loss：对同 ref8 的 Es48早层做局部 patch descriptor，保留 ref 轴，固定位置/覆盖规则且不得按生成效果选 patch，经一个共享投影送既有高分辨率 up style attention。直接展平8×48×48=18432 token 成本过高；若诊断支持，可预注册每 ref 16个覆盖笔画的局部小 patch 描述（共128 token），每个 patch 保留局部网格再线性投影，而不是整图4×4强池化。patch 尺寸、有效位、重复采样和空白 fallback 必须在看到候选输出前固定；这是一条另批 T 臂，不与 L 臂同批堆叠。

**96 diffusion 能否画？**[代码+推断] 训练直接在 `target_image` 上加像素噪声、预测同 shape epsilon，并重建 x0（`V/train.py:429`）；数据 native96且拒绝 resize（`:601`）。这里没有“先压缩到低分辨率 VAE latent”这个必经瓶颈，因此96网格上的纹理不存在由接口规定的绝对禁区。**但 GT 有、条件送达只是必要线索，不是充分保证**：局部条件可辨性、训练频率、损失偏好、网络利用与有限步采样都可能限制它。当前 loss 含 epsilon MSE、content perceptual 和 offset 项（`:440`），不能先断言换条件必然恢复细纹理。

**零训练验证与风险。**固定 ckpt，在原生96纹理阳性题本比较：(a) full-noise正常生成；(b) 已知GT轻/中度加噪后的单步 x0 预测或重建诊断；(c)相同图的去纹理控制；并在训集/val分开报告。b 若成功只说明“部分像素证据已在 noisy input 时能保留”，不证明从噪声可合成；a 能合成而错 ref 不改变纹理，说明可画但未按 ref 控制。sampler增加步数可作单独成本匹配诊断，不与新条件臂混在主比较。飞白可能与破碎伪影、细字重混淆；必须做内部纹理属性盲评、身份和伪影非劣，而不只追求高频能量或 VGG 距离。

### 2.3 第三层——每字设计决策：星星 i 点、空心 1

**特征本质与可辨识性。**ref8若没有该设计约束，无法唯一推断作者对i/1的选择；即使其他字显示装饰倾向，也不足以确定装饰的目标位置和形式。固定 refs、bank、目标字符，相同输入可以对应不同真实设计；检索只能偏好一个兼容解（`reports/IDEA_ICLR_SCORE_20260908.md:100`）。允许合适库先验，不等于把库猜测称为目标个体事实。

**Δ 本该是候选载体，但不是直接描画命令。**实际各尺度：

\[
\Delta_c^{(l)}=\sum_{j\in J(R)}\alpha_j E_c^{(l)}(B_{j,c})-E_c^{(l)}(B_{0,c}).
\]

`V/train.py:188` 选择 J/α；`:191` 读取 donor **同目标字符**；`:193` 读 Content；`scripts/hrfont_feature_cache.py:201` 按尺度相加再减中性底。若选中 donor 的i确为星星点、Ec保留该差异，它就可能在 Δ 中。并且 Ec cache 含原RGB96项（`scripts/hrfont_feature_cache.py:11`），但**被构造不等于被消费**。

**更具体的消费瓶颈已可定位：**默认 up block 是普通 / RSI / RSI / 普通（`V/src/build.py:19`）；RSI 的索引为1、2，读取 `structure_features[-upblock_index-2]`（`V/src/modules/unet_blocks.py:750`）。结合5尺度列表，它们读取 **24×24和48×48**；原RGB96残差与两项12×12不是这两个RSI块直接的 structure 输入。执行机须用 resolved architecture/hook 再确认，本文不把默认代码当作运行时断言。

在 `OffsetRefStrucInter` 中，Δ 经 GroupNorm、1×1、LayerNorm 后作为 attention 的 **Q**；K/V 来自 UNet skip（`V/src/modules/attention.py:305`、`:319`），最后投影为18-channel 3×3 DCN offset（`:299`、`:330`）。随后用该 offset 重采样 **skip，不是 donor Ec**，并经既有 residual correction 后送卷积/style attention（`V/src/modules/unet_blocks.py:761`）。所以 Δ 的星星残差不是作为值特征/像素直接搬进生成器；它必须被翻译成采样位置，再由后续网络形成轮廓。这是比“RSI只会低频”更确切的接口限制。

**不能由此声称 DCN 禁止拓扑变化。**这不是光滑可逆形变约束的系统：DCN 的离散多点采样、卷积与生成网络可改变阈值后的连通/孔洞；代码也未做严格低通。因此“星星/空心必被 DCN 丢弃”尚无证据。更合理的假设是：offset-only 间接承载、归一化、训练目标与网络偏好可能不利于复杂局部增删。要观察 source→offset→warp correction→output 的响应，而不只量 offset 大小。

**平均/稀释风险有一个实证样例，但不等于全库平均。**`reports/f03_test16_strat/neighbors_FZHuoYYJW-T.json:13` 的10个权重约0.099335–0.100588，确实近均匀。228是候选池，不是228项混合；代码先按逐 ref 同字 cosine 的均值选top10，再在入选者上softmax（`scripts/hrfont_delta_v2.py:99`、`:119`）。该 JSON `meta.entropy=5.4293` 是**截断前候选池分布熵**，不是top10熵；不能据此计算top10 effective-N，须从返回权重重算。

若只有一个入选 donor 有特效，另九个没有，其线性贡献可能仅约1/10；位置不同、孔洞不同会让空间差异相消或形成模糊共识。但 Ec 非线性，不能断言“特征均值=像素平均”，更不能说10个同族同特效的近均匀混合一定坏。库里有设计族仍可能根本没进 J：当前检索也用 Es pooled h，可能主要按字重等粗属性选邻居。因此需区分**选错邻居、混合抹掉、Ec不保留、RSI不消费**四种失败。

**最小修改候选与收益风险。**先做 §3 的单 donor/同族子集/原top10零训练干预；若证实混合冲突，才另批更尖 α 或同设计模式内残差，保持“Δ=相对B0的方向先验”。温度锐化并不能修复错误排序，也可能放大错误top1。若 Δ 的正确局部信息明确存在且通过offset-only不能作用，才另批**单尺度 Δ 局部值通道**：保留当前RSI，把已消费的48×48 Δ 的固定局部描述经共享投影送既有 up context；不先添加 gate、不把 ref Ec 混入 Δ。它与 P+L 是不同问题的备选，不一起上线；新增通道须与 P 控制同端点训练，wrong-char Δ 干预确认不是仅加容量。

同族/特效 donor 的GT知情选择只能叫**oracle诊断上界**；测试字体自身/同lineage不得作为正式库条目。普通方法中的模式/权重选择只能依 refs 与合法bank属性，不能读取目标GT。若 ref无法选出唯一模式，可称多候选先验或显式设计控制，不以“恰好猜中GT”当消除不可辨识性的证据。

### 3.2 特效沿 donor→Ec→Δ→offset→图像的审计（Z-DELTA）

**冻结：**先F2无support固定checkpoint、Content、Es条件、噪声、sampler/步数/CFG、A96预处理。记录checkpoint/cache SHA，逐字符J、α与来源，保存各实际消费尺度的统计。需要执行机推理wrapper/hook；本次没有实现，也不提供未核对的“现成CLI开关”。

1. **存在与检索命中：**人工标合法train donor的目标i/1等是否有指定特效及其位置，区分库无、库有未入J、已入J。计算实际top10熵、effective-N=`1/Σα²`、特效总权重、各设计模式的质量与位置差异。不能拿单个近均匀样例代表全体16字体。
2. **编码保留：**比较donor原RGB、Ec48/24及相对B0残差；用同字特效/无特效配对检查局部区域差异。RGB可见而Ec48/24不可辨时先定位encoder/尺度，不能责怪softmax。特征距离本身不保证生成可读。
3. **混合稀释：**保持J，比较原α、同J均匀、固定温度锐化、top1；另设“已标有特效的单donor”与“同特效模式子集”作为oracle诊断上界，并设字重/尺度相近的无特效donor负控。每种仍构造 `Ec(donor,c)−Ec(B0,c)`，不是偷偷切绝对源。若原top1不含特效，锐化阴性不判RSI无效；有特效donor输入阳性也不能证明ref能正确选到它。
4. **幅值与语义分开：**同时报告原始残差和逐尺度RMS匹配的敏感性版本，近零源不强行归一化。RMS只控幅度，不使两输入同分布；GroupNorm还可能消掉简单标量剂量效应，故仅扫λΔ不是充分判决（`V/src/modules/attention.py:305`）。空间shuffle/wrong-char为破坏控制，需保留shape并报告偏离程度。
5. **消费响应：**在同噪声轨迹外另做固定`x_t,t,skip`的局部前向，分别记录offset改变、`zero_conv(warped−skip)`改变、epsilon/x0局部预测与最终图像特效。避免扩散轨迹分叉让“offset变了”无法定位。只做观察性hook/替换结构输入，不改权重。
6. **尺度干预：**只换Ec48或Ec24的Δ，另一尺度保持原张量；可做逐通道空间平滑及RMS匹配，检查局部特效响应。这测的是**特征空间空间频率利用**，不是证明某特征通道等于像素高频。未消费的RGB96项变更应做负控；若影响输出需查真实执行接口是否不同。

|---|---|---|
| 库有但原J无，oracle donor可救回 | 检索覆盖/排序是瓶颈候选 | 不能只靠调τ解决，也不证明部署可选oracle |

## 4. Q2：one-shot/few-shot差异只在结构，是否 Δ 输入有问题

### 4.1 分工并非互斥；Mode D 的变量是 Es，不是 Δ

**[代码]**Δ主要通过RSI offset影响skip几何；Es在MCA和up cross-attention影响隐状态（§1、§2.3）。但没有一个约束把“宽窄粗细方圆”专门分给Δ、把“笔刷”专门分给Es。Es当然可以编码/调节字重和几何；而Es改变的down skip又作为RSI的输入，即使Δ张量固定，offset也可能随之改变（`V/src/modules/attention.py:301`）。

因此对Mode D应作如下判定：

- **不是 Δ 输入变化造成了 s1/s8 差别。**若Mode D合同成立，两者J/α/Δ相同；差别是Es条件变化及其与生成/RSI的交互。这一观察反而证明Es条件不是完全被忽略。
- **与“细风格条件不足、模型主要响应粗属性”一致。**但不足发生在编码、池化、聚合、注意力消费还是损失，没有被分离。没有细纹理不能直接叫“Es通道失效”。
- **既不能证明Δ正常，也不能替Δ免责。**固定的Δ仍可能提供一致但偏中庸的先验，削弱所有style条件下的局部特征。该主效应在“只改Es”的比较里没被干预。

若另一次“one-shot/few-shot”同时把检索query也改成1/8，则Δ也变了；必须逐图读取metadata，不可把那种实验套入Mode D的结论。已有index只支持本节限定合同（`reports/f03_test16_strat/browse_index.json:1`，`note`、`methods`）。

### 4.2 F2-s1 与 F1-s1 现成数据能否判决

**不能作因果判决，只能浏览。**F1是@30k mid、official `Ec(永)`；F2是@75k、style永但Δref8。它们不仅源不同，checkpoint权重、训练轨迹和端点也不同；“都是s1”没有消除这些混杂。index `note` 本身明确禁止把F1对F2/F3当公平消融（`reports/f03_test16_strat/browse_index.json:1`）。

即使未来有F1/F2同40k或80k，且其它训练合同matched，那测的是**训练采用某结构源的整体处理效应**；不是固定模型中“Δ此刻压制了style”的直接判决。二者均有价值，不可互相替代（旧评审 `reports/IDEA_ICLR_SCORE_20260908.md:167`）。

### 4.3 最小可执行固定 checkpoint 判决（Z-SOURCE）

**主实验：F2@75k一个checkpoint、无support。**选§3的固定val题本；同Content、Es“永”的cache map、同初始噪声3407/3408、同sampler/步数/CFG（复用实际baseline配置，不能自行换快采样）、相同conditional/unconditional规则。每个样本只替换传给 `model.forward(structure_features=...)` 的列表：

| 格 | structure输入 | 目的 |
|---|---|---|
| S-Δ | 原ref8检索的Δ | 原baseline |
| S-O | 同目标字体`Ec(永)`的多尺度cache，沿official构造 | **核心反事实：同模型、同style，仅改结构源** |
| S-0 | 同shape全零source | 训练source_drop见过的近域对照；不是完全关RSI |

实现边界明确：wrapper在原构造结构张量之后、传入模型之前切换来源；style tensor、Δ query、Content均不能跟随来源重算。S-O沿 `V/train.py:169`；S-Δ沿`:185`；S-0沿source-drop做法。先断言各尺度shape/dtype/device、Content/style hash一致；逐样本保存source与噪声hash、sampler配置、结果和属性评分。现有训练配置`rsi_source`说明此构造可行，但**未确认执行机sample wrapper有现成参数**；本次不修改它，实施需另批。

注意 `structure=None` 会在model里转零（`V/src/model.py:57`），而零source经GN/偏置后仍可能产生offset；S-0不等于RSI bypass。可另设 `rsi_enabled=False` 诊断所有RSI支路的影响，但这是额外干预，且不等价F0模型；本次不将其当最小三格的必需项。无条件CFG分支保持baseline的source置零/保留规则，不能仅一格改变它。

**最小三格之后再做交互：**以同checkpoint将style改成ref8 mean，保持同一Δ及official永source，再跑三格，形成 **style{s1,s8}×source{Δ,official,0}** 六格。若资源只够两格，先S-Δ/S-O的s1配对，但只能判断该style条件下的源敏感性，不能检验是否特异压制多ref。条件敏感性可写成：

\[
I=[A(s8,O)-A(s1,O)]-[A(s8,\Delta)-A(s1,\Delta)],
\]

其中A为预注册的可观察属性匹配评分，非L1单指标。I只量该固定模型中的干预交互；需结合四格各自基线与身份/质量，不能把“s8变化更大”自动称更好。

**判决规则（建议冻结）：**

- 若S-O/S-0相对S-Δ稳定恢复ref可见的笔触/收笔，且非单纯变黑/变斜、身份与无伪影满足非劣，则支持“当前Δ条件/读取抑制了这些属性”；再用Z-DELTA拆混合与接口，**不是立刻删除Δ**。
- 若S-Δ有清楚几何收益但细属性三格都缺，优先ref局部层；这仍不是Δ无害证明，只说明移除/替换源没在该模型救回细风格。
- 若S-O更差，不能宣布Δ正确：F2训练主要见残差，official是绝对、异字源，存在OOD。加逐尺度RMS匹配敏感性报告；S-0因source-drop是重要辅助。必要时在F1固定ckpt做反向Δ/official/0测试：只偏爱各自训练源，提示适配而非语义优劣。
- 若源切换全部几乎不变，检查真实RSI correction与原执行接口是否启用，再判断是否忽略结构源；若只identity变、style不变，不能宣称对笔刷有效。

单个checkpoint零训练不能对“Δ结构构造是不是方法上的错误”作最终因果裁决。需要改α时，保持P style和其它合同，申请原α对候选α的20k/40k matched臂；需要证明official替代更好时，同样要同端点、同源drop训练对照。未通过新层级/源探针，不新增这些训练。

### 4.4 Q2 的最终答案

**不是简单的“Δ的错”；也不是已证“不是Δ的错”。**当前最强证据是：Es条件变化主要被表达为粗几何，且去掉8-ref平均没有普遍救回细风格；这使局部ref证据/读取不足成为优先排查项。只有看到“合法正确donor→残差含特效→原混合压弱→受控替换恢复”，或固定源交互明确压制ref属性，才优先改α/残差构成。正确Δ有信号却经offset链不传递，则优先改读取接口，而非继续盲目锐化检索。
