# 3. 启动/托管脚本 review

- **launch 不是后台/nohup。** `subprocess.run` 前台阻塞，调用终端断连可能影响训练；真正的 session 隔离只存在 watchdog 的 `Popen(..., start_new_session=True)` [launch_cn2west_ft_v2_e1.py:127](../scripts/launch_cn2west_ft_v2_e1.py#L127) [watchdog_e1_ft_v2.py:154](../scripts/watchdog_e1_ft_v2.py#L154)。文档应明确 full run 必须由 watchdog/systemd/tmux 托管，或 launcher 自己写 PID/log 并 detach。
- **watchdog 没有 60s heartbeat，也没有 STOP 语义。** status 只在 attempt/start/completed 更新，`proc.wait()` 期间不刷新；故无法按 >5min 心跳告警，STOP 文件也不会阻止自动重启 [watchdog_e1_ft_v2.py:149](../scripts/watchdog_e1_ft_v2.py#L149) [watchdog_e1_ft_v2.py:164](../scripts/watchdog_e1_ft_v2.py#L164) [watchdog_e1_ft_v2.py:200](../scripts/watchdog_e1_ft_v2.py#L200)。这是**高风险运维缺口**。
- **自动 resume 不精确且会从旧的 last_state 优先。** finder 无论 global_step milestone 是否更新，固定优先存在的 `last_state`; 当前两者都是整 1k/5k 时通常相等，但异常写入或拷贝后可能选较旧状态 [train.py:50](../code/variants/cn2west_ft_v2/FontDiffuser/train.py#L50)。应比较所有候选 state 内的 global_step，并验证三权重+state 原子完整性。
- **里程碑只部分落实。** 5k 目录包含 full train state 并被看板评估；1k 只有覆盖式 `last_state`，没有“最近 5 个 1k”滚动保留，也无 best checkpoint 指针/复制 [train.py:349](../code/variants/cn2west_ft_v2/FontDiffuser/train.py#L349) [EXPERIMENT_PLAN_CN2WEST_V2.md:55](./EXPERIMENT_PLAN_CN2WEST_V2.md#L55)。val 由独立 refresher发现 checkpoint 后调度，不是训练事务的一部分；失败仅写日志，训练仍前进 [refresh_e1_dashboard.sh:83](../scripts/refresh_e1_dashboard.sh#L83) [refresh_e1_dashboard.sh:132](../scripts/refresh_e1_dashboard.sh#L132)。
